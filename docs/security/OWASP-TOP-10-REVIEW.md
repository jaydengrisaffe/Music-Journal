# Music Journal OWASP Top 10 Review

This review evaluates Music Journal against each OWASP Top 10 category. Each category was reviewed to determine whether it applies to the current application, whether existing controls already address the risk, and whether additional action was needed during Milestone 2.

| # | Category | Status in Music Journal | Action |
|---|---|---|---|
| A01 | Broken Access Control | Found: `FavoriteTracksController` did not require authentication for all actions. An unauthenticated user could access the Add Favorite page and attempting a search caused an error because no authenticated user existed. | Fixed — added controller-level `[Authorize]` so all favorite-track actions require authentication. User-specific queries are also restricted using the authenticated user's ID. |
| A02 | Cryptographic Failures | Reviewed: Spotify API credentials had previously been stored in a tracked development configuration file. | Fixed — the exposed credentials were rotated, and the current Spotify credentials are stored using .NET User Secrets instead of tracked configuration files. `appsettings.Example.json` contains only placeholder values for setup documentation. |
| A03 | Injection | Reviewed: database operations use Entity Framework Core LINQ queries rather than constructing raw SQL from user input. No raw SQL queries were found in the reviewed controllers. | No change needed — existing Entity Framework Core query handling reduces the risk of SQL injection. |
| A04 | Insecure Design | Reviewed through the STRIDE threat model, including authentication, user-specific data, state-changing requests, external services, database access, and credential management. | No additional change needed — identified design risks and their mitigations are documented in `THREAT-MODEL.md`. |
| A05 | Security Misconfiguration | Reviewed: detailed exception information is visible while the application runs in Development mode. Production configuration uses a generic error handler and HSTS instead of exposing detailed exception information. | No change needed — `Program.cs` already separates development and production error handling and enables HTTPS redirection/HSTS for production. |
| A06 | Vulnerable and Outdated Components | Found: the dependency audit identified `SQLitePCLRaw.lib.e_sqlite3` version 2.1.10 as a High-severity vulnerable transitive dependency brought in through `Microsoft.EntityFrameworkCore.Sqlite` 9.0.10. | Fixed — updated `Microsoft.EntityFrameworkCore.Sqlite` from 9.0.10 to 9.0.22. A second vulnerability scan reported no vulnerable packages. |
| A07 | Identification and Authentication Failures | Reviewed: user registration and login are handled by ASP.NET Core Identity, and authenticated-only functionality is protected using `[Authorize]`. | No additional change needed — the application relies on ASP.NET Core Identity rather than implementing custom authentication or password handling. |
| A08 | Software and Data Integrity Failures | Reviewed: the application does not accept software updates, executable code, or serialized application objects from users. Project dependencies are managed through NuGet and source changes are tracked through Git/GitHub. | No change needed — no software or data integrity vulnerability was identified in the reviewed application workflows. |
| A09 | Security Logging and Monitoring Failures | Reviewed: the application uses ASP.NET Core logging for application errors, but it does not currently implement dedicated monitoring for security events such as repeated failed login attempts. | Accepted for current scope — existing application logging is retained, while more detailed security-event monitoring is documented as a future improvement. |
| A10 | Server-Side Request Forgery (SSRF) | Reviewed: no application feature was identified that allows a user to provide an arbitrary URL for the server to request. External API communication is performed through configured application services. | No change needed — no user-controlled server-side request functionality was identified in the reviewed application. |
